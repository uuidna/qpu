# QPU full stack

The source of payloadcms.com (MIT) is the full stack, forked under site/: its 12 collections, 30 blocks, 5 globals and 10 fields kept. Applied: `src/blocks/Qpu/config.ts` (the qpu block, the shape every tools/call result carries in _meta.payload), registered in payload.config blocks and the pages layout; `src/components/blocks/Qpu/index.tsx` (the renderer: the page asks the Worker for the block and carries its widget), mapped in RenderBlocks; `src/payload.qpu.config.ts` (search and multi-tenant beside the site's four plugins, the database the RAID); `src/collections/Tenants.ts` (the multi-tenant plugin's own collection: the hosts that name the tenants). The catch-all makes prefixes useless: a UUID is one address — the entry's JSON when the client accepts application/json (the entries collection's own door), the block's page otherwise; the list is /api/entries; /mcp is the MCP plugin's /api/mcp and /.well-known/qpu.json the endpoint /api/qpu; no Worker behind any of them. Deploy at Cloudflare beside this Worker; every step at whole uptime: configure { kind: 'migration' }.
