# QPU · standards

the standards fused: schema.org on every block, page and offer; ISO 8601, 639-1, 4217 and 3166-1 in every date, language, price and country, validated against the CLDR lists discovery reads as contracts

Generated by `payload { scripts: { skills: true } }` from the toolbox itself (3 tool(s), 4 example(s), 3 direction(s)); edit the toolbox, never this file.

## How a client uses it

jsonld needs no fetch. codes: the client fetches the three CLDR documents the plan names (GET, free, no credential) and calls codes with them; a code the standard does not know is a lead. The discover step reads schema.org's vocabulary and the CLDR lists as contracts; every tools/call result carries _meta.jsonLd and every documentation page a JSON-LD script.

## Examples

- `standards-validate`: validateStandards validates against all standards via Payload's standard implementation, in the cheapest possible slices: every standard (a codes list by a select/validate against CLDR, a vocabulary by schema.org JSON-LD, a reference by the generated config and its field validations) covered, split into content-addressed slices of six so validation, reindexing (referenceIndex) and cleanup (purify, the RAID GC) run per slice as a job — the cheapest unit, an unchanged slice skipped by its address; the covered and the uncovered make the standards.
- `standards-iso-online`: Every ISO dimension is asked of the ISO Open Data page.
- `standards-iso-page`: The ISO Open Data page is the way in.
- `standards-iso-joined`: One row of the open dataset verifies the dimension its reference names.

## Directions it tests itself in

- server only: JSON-LD shapes on fixtures; CLDR fixtures read into code sets; the tree's codes validated

- toolbox → toolbox: offers come from the billing catalogue, locales from the language toolbox, the contracts from discovery
