the docket as a database: MongoDB's query and update language ported as pure functions over content-addressed entries, so any document framework (Payload first) stores on the RAID through its mongodb adapter

## How a client uses it

A client that is a database adapter (Payload's mongodb adapter interface) reads a collection's rows from the docket (GET /docket?collection=…, the bodies), calls mongo with the op and the rows, and writes the entries the tool returns (POST /docket, writer role) or deletes the ids (DELETE, admin role; a linked entry is refused and kept). Every query is pure and recomputable; every write is content-addressed and linked to what it replaces.

## Examples

- `mongo-find`: A Mongo filter over documents read from the docket: operators, array membership, sort; the match is computed here, the storage is the docket.
- `mongo-update`: An update computed as a new document and a new entry linked to the one it replaces: entries are immutable and content-addressed, so history is kept.
