## How a client uses it

Inward: call extend with a host (direction in); fetch the one request it emits, adding the tenant's bearer token where the host asks for one (QPU_MCP_TOKEN_<HOST>); call again with tools and the host's doors join the catalogue as host:tool. Serve one: extend with call { tool, arguments }; fetch the request; call again with answer. Outward: extend with direction out gives the registration (mcpServers fragment) any MCP client mounts. extend { connector: true } is that MCP: Cursor, Claude, Gemini, and any other model mount https://qpu.uuidna.com/api/mcp, and quantum demand stays on this register. Adapter: extend { adapter: true } lists the models whose quantum demand this register computes; extend { adapter: { model, call } } runs that call here and returns the UUID receipt. extend { adapter: { next: true } } rotates every open quantum lead, and carries each task as a pages instance and a products instance in memory on the UUID stream of that address and its fourteen witnesses. call may be the model's own envelope: a Gemini generateContent response, a Claude tool_use list, a Cursor tools/call, or a tool_calls list. extend { claude: { compat: true } } narrows every quantum tool to strict tool use on this register. extend { cursor: { compat: true } } certifies every quantum tool as an MCP tool Cursor accepts, on this register. Sell: extend { cursor: true } plans the Cursor TypeScript SDK module that mounts this catalogue and calls stripe catalogue, then stripe plan; the harness runs it with CURSOR_API_KEY, which the tree never holds. The discover tool extends the default hosts (the unit, this tree, Cloudflare's eight servers) on every run; a tenant names its own hosts with QPU_MCP_HOSTS[_<TENANT>].
